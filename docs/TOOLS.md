# Инструменты и плагины: SDK v1

Подсистема соответствует разделению Project.txt: ToolEngine в application валидирует вызов и публикует ToolExecution/ToolExecuted; infrastructure обнаруживает манифесты, хранит реестр и запускает процессы. LLM видит ToolSpec, но не управляет установкой пакетов.

## Добавление

Скопируйте `plugins/text_utils` как образец. Имя каталога должно совпадать с `id` в plugin.json. Перезапустите систему кнопками Stop/Start. Плагин автоматически регистрируется, менять Python-реестр не нужно. Горячая перезагрузка во время инференса не предусмотрена.

Манифест: sdk_version=1, id (строчные латинские буквы, цифры и подчёркивания), enabled=true, entry="plugin.py", tools=[...]. Каждый tool содержит name, description, необязательный function (по умолчанию name), permissions и parameters. Параметр: type, description, required (по умолчанию true), enum (необязательно). Поддерживаются string, integer, number, boolean, array, object; вложенные схемы пока не валидируются.

Имя для LLM: `id__name`. Так два плагина могут иметь одноимённые функции. Повторные имена внутри одного манифеста отклоняются; некорректный плагин логируется и не мешает другим.

SDK намеренно не требует отдельного пакета: это обычная sync или async Python-функция с именованными JSON-аргументами. Возвращаемое значение должно сериализоваться в JSON. Отсутствующие необязательные параметры нужно покрыть Python-значениями по умолчанию. Импорт модулей и выполнение происходят в дочернем процессе; print перенаправляется в stderr. Процесс создаётся на каждый вызов, поэтому глобальное состояние между вызовами не сохраняется.

## Зависимости

Без сторонних библиотек плагин сразу запускается текущим Python. Если есть зависимости, добавьте `"requirements": "requirements.txt"` в манифест и файл с закреплёнными версиями, затем из корня LinaAI выполните:

```powershell
.venv/Scripts/python.exe tools/manage_plugin.py install text_utils
```

Создаётся `.plugin-envs/text_utils`, pip устанавливает зависимости только туда. Общие зависимости Lina и других плагинов не меняются. Автообнаружение ничего не скачивает и не устанавливает. Плагин с requirements недоступен до успешного завершения установки (маркер .ready). После изменения requirements повторите install; для полностью чистой переустановки сначала remove-env. Среда не включается в архив проекта.

## Отключение и удаление

Установите `enabled: false` в манифесте либо уберите папку из plugins, затем Stop/Start. Для удаления его зависимостей:

```powershell
.venv/Scripts/python.exe tools/manage_plugin.py remove-env text_utils
```

Команда удаляет только отдельную среду; исходники сохраняет. Общий кэш pip остаётся. Удаление/переустановку среды выполняйте при остановленной Лине. Удаление самой папки плагина оставлено владельцу, автоматического удаления пользовательских данных нет.

## Ограничения и выполнение

Инструменты объявляют необходимые права: read (чтение), write (изменение файлов), network (доступ к сети), execute (запуск программ). Для внешних инструментов ни одно право не выдаётся автоматически, включая read. Модель видит доступные инструменты, но решение о разрешении принимает пользователь через интерфейс; инструмент не получает доступ до согласия. Автономный режим дополнительно сохраняет свой allowlist в behavior.autonomous_tools.

В лаунчере откройте Advanced Settings → Plugins, выберите плагин, затем инструмент. Галочки показывают выданные права; доступны только права, объявленные этим инструментом. Выдача и отзыв применяются сразу без Stop/Start. Права можно настроить и у выключенного установленного плагина. У недоступного плагина сначала нужно исправить манифест/установить зависимости.

Если при вызове не хватает прав, Лина показывает окно: «Плагин 'название' требует разрешение на 'список разрешений'. Разрешить ?». Можно разрешить текущий вызов, отметить «Запомнить для этого инструмента» или отказать. Закрытие окна, отсутствие ответа в течение двух минут и Stop не разрешают выполнение. Диалог не блокирует цикл событий приложения; Stop остаётся доступен. Ответ привязан к конкретному запросу и инструменту, просроченное согласие игнорируется. Реплики модели и текстовое «да» в чате сами по себе не выдают права.

Постоянные разрешения хранятся отдельно от манифестов в `data/tool_permissions.json`, файл исключён из Git. Они действуют для инструментов этого рабочего экземпляра Лины и сохраняются после перезапуска. Манифест объявляет требования, но не может самостоятельно выдать себе права. Отзыв блокирует следующие вызовы; уже принятые фоновые задания отменяются через jobs_cancel или Stop.

Проверка прав происходит перед запуском Python-кода плагина. Это контроль вызовов, а не изоляция ОС: доверенный Python-код технически имеет права пользователя, запустившего Лину. Не устанавливайте недоверенные плагины без отдельной изоляции процесса средствами ОС.

Обычный вызов имеет таймаут 15 секунд. Поле инструмента `timeout_seconds` задаёт другой положительный таймаут до 3600 секунд. На отмене или таймауте завершается worker и его активное дерево процессов (Windows: taskkill /T, POSIX: отдельная группа процессов). Плагин должен дождаться всех собственных операций до возврата результата: отделённые службы и процессы, переживающие родителя, не являются поддерживаемой моделью фоновой работы.

Размер JSON-ответа ограничен 64 КиБ, в LLM идёт до 4000 символов. Пример `text_utils__word_count` считает слова и символы без внешних зависимостей. GUI-менеджер подключён: расширенные настройки → Plugins. Открытие панели или Refresh Plugins перечитывает каталог. Чекбокс Enable Plugins управляет общей загрузкой внешних инструментов (встроенные остаются доступны). Галочка у плагина записывает enabled в его манифест; состояние и список инструментов обновляются. В подсказке отображаются требования и команда установки. Все изменения набора инструментов применяются на следующем Start; Refresh не заменяет активные обработчики. Ошибочный манифест показывается отдельно без доступного переключателя.

## Фоновые задания

Добавьте `"background": true` в описание конкретного инструмента. Вызов сразу вернёт JSON с `job_id` и `status: queued`; Лина сможет продолжить диалог. Это ещё не результат операции. Функция плагина выполняется до завершения в своём процессе и может быть обычной или async. Отдельное окружение на диске не занимает оперативную память, пока процесс не запущен.

Одновременно работают максимум два фоновых задания, ещё шесть ожидают без процессов. При заполнении очереди новый вызов отклоняется. Лимит общий для всех плагинов; два вызова одного плагина тоже могут работать одновременно, поэтому доступ к общим файлам нужно синхронизировать внутри плагина. Обычные инструменты и чат доступны, пока выполняются фоновые. По умолчанию время работы задания ограничено часом; ожидание в очереди в таймаут не входит.

Встроенные инструменты управления:

- `jobs_status(job_id)` — статус, прогресс, сообщение и результат/ошибка.
- `jobs_list()` — краткий список своих заданий.
- `jobs_cancel(job_id)` — отмена своего задания, включая ожидающее в очереди.

Статусы: queued, running, succeeded, failed, timed_out, cancelled. Доступ проверяется по пользователю, запустившему задание. Хранятся последние 100 завершённых заданий, результат каждого ограничен 4000 символами. Данные живут в памяти до Stop; восстановление после перезапуска не предусмотрено. Stop/выход отменяет задания и дожидается завершения процессов.

Прогресс необязателен и не вызывает LLM. SDK доступен в процессе плагина даже при использовании отдельного venv:

```python
import time
from lina_plugin_sdk import report_progress

def process_items(count=10):
    for index in range(count):
        time.sleep(1)  # Здесь выполняется полезная работа.
        report_progress(100 * (index + 1) / count, f"Обработано {index + 1}/{count}")
    return {"processed": count}
```

Сообщение прогресса ограничено 300 символами, SDK отправляет до четырёх обновлений в секунду (финальные 100% отправляются всегда). Статус читается по запросу; постоянный опрос моделью не нужен. О завершении, ошибке или таймауте показывается уведомление в трее, без вмешательства в текущий ответ чата.

Для проверки включите поставляемый `background_demo` в Plugins и выполните Stop/Start. Он ничего не скачивает и не меняет файлы. Попросите Лину запустить `background_demo__wait` на несколько секунд, продолжите диалог и запросите статус или отмену.

Фоновый режим не расширяет права инструмента. Например, загрузчик должен объявить network/write и получить эти права в лаунчере или через запрос при вызове, прежде чем менеджер поставит задание в очередь.
