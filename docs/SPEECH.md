# Распознавание речи

Путь записи: `ApiService` → `RecognizeSpeechCommand` → `RecognizeSpeechHandler` → `SpeechRecognizerPort` → `VoskRecognizer` → `SpeechRecognized` / `SpeechRecognitionFailed` → `ApiService`.

Presentation получает PCM от устройства ввода и отправляет команду с записью, частотой и уникальным `request_id`. Он подписывается на события результата, отображает ошибки и передаёт распознанный текст в существующий UI-путь отправки сообщения. Чужие, повторные и поздние события после закрытия UI игнорируются. Прямых вызовов распознавания и владения моделью в presentation нет.

Application-хендлер проверяет запись (mono signed 16-bit PCM, 8–48 кГц, до 60 секунд), состояние runtime и результат распознавания. Пустой текст и ошибки провайдера становятся `SpeechRecognitionFailed`; успешный текст — `SpeechRecognized`. Отмена не публикует успешный результат. Доступ к распознавателю идёт через порт, без зависимости application от Vosk и Qt.

Infrastructure загружает Vosk лениво, выполняет обработку в отдельном потоке и переиспользует модель. DI-конфигурация задаёт `vosk_model_path`, разрешает относительные пути от корня приложения и владеет жизненным циклом провайдера. Stop отменяет UI-команды, дожидается распознавания и закрывает провайдер; следующий Start связывает хендлер с новым экземпляром.
